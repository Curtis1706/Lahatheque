Guide d'Intégration Partenaire • Mode Catalogue Seul

Éditions LAHA • Plateforme Académique LAHAThèque • Version 2.0

Public cible : Développeurs, architectes logiciels et administrateurs techniques de portails universitaires, LMS et bibliothèques partenaires intégrant le catalogue académique officiel LAHAThèque et la liseuse sécurisée.

1. Principes & Fonctionnement

Le mode d'accès « Catalogue Seul » permet à votre système d'information académique de :

  • Explorer et synchroniser le catalogue : Récupérer les métadonnées officielles des ouvrages (titres, auteurs, résumés, disciplines, ISBN, couvertures).
  • Vérifier les licences des bouquets : Contrôler en temps réel l'inclusion d'un ouvrage dans les bouquets souscrits par votre université.
  • Instancier des sessions de lecture sécurisées : Générer une URL de liseuse éphémère et filigranée en un clic pour vos étudiants via l'API, sans création de compte supplémentaire.
  • Personnaliser la liseuse : Appliquer l'identité visuelle de votre établissement (logo, nom, palette de couleurs).
  • Consulter les statistiques d'usage : Suivre les métriques de consultation de votre campus.

2. Le Flux d'Intégration en 4 Étapes

  1. Authentification Machine-to-Machine : Échangez votre Client ID et votre Client Secret contre un jeton Bearer OAuth 2.0 (valide 10 heures) sur POST /api/v1/oauth2/token/.
  2. Exploration du Catalogue : Consultez la liste des ouvrages éligibles via GET /api/v1/partner/catalog/.
  3. Création d'une Session de Lecture : Initiez une session de lecture sécurisée avec POST /api/v1/reader/sessions/ en transmettant le book_id et les informations de l'étudiant.
  4. Ouverture de la Liseuse : Redirigez l'étudiant vers l'URL sécurisée retournée (reader_url).

3. Pré-requis & Variables d'Environnement

Insérez les variables suivantes dans votre fichier .env ou votre gestionnaire de secrets applicatifs :

LAHATHEQUE_CLIENT_ID={{ client_id }} LAHATHEQUE_CLIENT_SECRET={{ client_secret }} LAHATHEQUE_API_URL=https://api.lahatheque.com/api/v1

4. Personnalisation de la Liseuse (Objet theme)

Propriété Type Description
brand_name String (2-50 car.) Nom de votre université affiché dans la barre d'outils supérieure.
brand_logo_url URL HTTPS (PNG/SVG) Logo officiel de l'établissement.
primary_color Code HEX (ex: #1B2A4E) Couleur principale de la barre d'outils.
accent_color Code HEX (ex: #B08D42) Couleur d'accentuation dorée des boutons actifs et de la pagination.
background_color Code HEX (ex: #0F1A33) Couleur de fond du cadre de lecture.
text_color Code HEX (ex: #FFFFFF) Couleur de contraste du texte et des icônes.

5. Référence Technique des Endpoints

5.1 Demande de jeton OAuth 2.0

POST /api/v1/oauth2/token/ Content-Type: application/x-www-form-urlencoded grant_type=client_credentials&client_id=VOTRE_CLIENT_ID&client_secret=VOTRE_CLIENT_SECRET

5.2 Consultation du Catalogue Partenaire

GET /api/v1/partner/catalog/?discipline=droit&search=civil Authorization: Bearer <access_token>

5.3 Création d'une Session de Lecture

POST /api/v1/reader/sessions/ Authorization: Bearer <access_token> Content-Type: application/json { "book_id": "uuid-du-livre", "external_user_id": "ETU-2026-9988", "user_display_name": "Jean Dupont", "user_email": "jean.dupont@universite.bj", "theme": { "brand_name": "Université d'Abomey-Calavi", "primary_color": "#1B2A4E", "accent_color": "#B08D42" } }

6. Bonnes Pratiques de Sécurité

  • Conservation du Secret Client : Ne stockez jamais le client_secret dans le code frontend (React, Vue, mobile). Tous les appels doivent être relayés par votre serveur backend.
  • Sessions Éphémères : Les jetons de lecture sont à usage unique et sécurisés par signature cryptographique. Ne mettez pas en cache les URLs de lecture.
  • Filigrane Dynamique : Chaque session est personnalisée avec le nom et l'email de l'apprenant pour prévenir la copie illicite.
